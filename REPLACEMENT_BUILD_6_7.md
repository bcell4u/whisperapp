# Build WhisperRecorder 6.7 — Qwen 0.6B + llama.cpp only

1. Use the **complete replacement source ZIP**, not an overlay of files onto old Git contents. For upgrades use the accompanying verified patch against pristine **6.5.22** and inspect deletes: the old `transcribenative/` tree and `TranscribeCppBackend.kt` must be absent in the actual Git checkout (`git status`, `git ls-files`). Keep signing secrets and user recordings private.
2. Push source to a test branch. In GitHub choose **Actions → Build Android APK → Run workflow** and keep `build_variant=debug` (manual, safe default). The script fetches the pinned `llama.cpp` v0.6.0 SHA, builds the ARM64 dotprod decoder, runs production source guards and JVM tests, assembles debug, runs Android lint and audits APK contents.
3. Download the `WhisperRecorder-build-<run>` artifact, inspect build proof, digest, lint exit/report, packaged native libraries and DEX checks. **No `libtranscribe_cpp_jni.so` and no 1.7B model card** should appear. The package must include `libwrqwen06.so` and Qwen 0.6B metadata. Debug app ID is `com.example.whisperrecorder.dev` and `versionName` is `6.7.0-dev`; `versionCode` is 67000.
4. Install the debug `.dev` artifact **beside** 6.5.22 on qualified Samsung S26 SM-S942U. Download both verified Qwen assets on demand (~1.20 GB combined), select Use, confirm the model uses **QNN/HTP encoder with CPU fallback disabled** and llama.cpp Q8_0 decoder, and run short (<12 s), boundary (13–24 s) and ~220-second lecture transcription. Validate cancellation, transcript quality/saving and performance.
5. Check Whisper, Parakeet GPU/NPU, Omi, speaker diarization, recording, export, playback, SAF and other production behavior. Only then consider an explicitly selected release build with original signing credentials and a backed-up production upgrade.
